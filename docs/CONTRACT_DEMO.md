# Verification, Assurance, and Comparability Contract Demo

**Status:** NON-NORMATIVE

This deterministic demo makes the contract flow visible using frozen local
fixtures. It performs no paid API call, network lookup, ambient trust discovery,
or ambient clock read.

## Run

From the repository root:

```bash
python3 examples/contract_demo/run_demo.py \
  --output-dir /tmp/aelitium-contract-demo
```

The script first confirms that the committed bundle bytes still match their
deterministic fixture recipe. It then invokes the public machine-readable CLI
surfaces and validates every JSON output against its packaged schema.

## Flow

```text
frozen declared-interaction fixture
          |
   signed evidence bundle
          |
  offline bundle verification
          |
  verification-result.json
          |
   assurance-result.json
          |
 verify both comparison inputs
          |
   explicit comparison basis
          |
  comparison-result.json (CHANGED)
          |
strict second comparison
          |
not-comparable-result.json (NOT_COMPARABLE)
          |
 bounded interpretation.txt
```

The left bundle is
`conformance/fixtures/bundles/signed_valid`. Its recorded interaction fields
were generated by the deterministic fixture recipe from a fixed model label,
fixed messages, fixed response text, fixed timestamp, and fixed test-only
Ed25519 key. The fixture key is public test material and must never be used
outside tests.

The `CHANGED` comparison uses
`conformance/fixtures/bundles/full_b_changed_response`, which has the same
selected invocation identity and a different selected response. The strict
refusal uses `conformance/fixtures/bundles/model_changed`, whose selected
invocation identity differs.

## Outputs

| File | Contract and expected conclusion |
|---|---|
| `verification-result.json` | `aelitium-verification-result-v1`, `status=VALID` |
| `assurance-result.json` | Exact embedded `aelitium-assurance-result-v1` extracted without reinterpretation |
| `comparison-result.json` | `aelitium-compare-v1`, basis `INVOCATION_IDENTITY_V1`, result `CHANGED` |
| `not-comparable-result.json` | `aelitium-compare-v1`, strict mode, result `NOT_COMPARABLE` |
| `interpretation.txt` | Deterministic bounded key/value rendering of selected states and non-claims |

The assurance output visibly includes:

```text
payload_integrity=VALID
signature_validity=VALID
trusted_signer_identity=UNESTABLISHED
freshness=NOT_EVALUATED
authorization=NOT_EVALUATED
```

The valid bundled signature therefore remains separate from independent
signing-key acceptance. Freshness and authorization remain non-evaluated
because the demo supplies neither a Freshness policy nor an authorization
evaluator.

`comparison-result.json` reports `CHANGED` only because matching validated
invocation identity hashes permit comparison and the selected response hashes
differ. Its claim-boundary array includes `model_drift_not_established` and
other explicit limits.

`not-comparable-result.json` has `response_relationship: null`. Different
selected invocation identities do not permit a response-change conclusion,
even when another field appears similar.

## Reproduce the corpus independently

The public conformance runner exercises all 44 frozen vectors:

```bash
python3 conformance/run.py
```

Maintenance-only recipe checks are:

```bash
python3 conformance/build_fixtures.py --check
python3 conformance/build_vectors.py --check
```

The normal runner consumes committed artifacts and never regenerates them.

## External evidence branch

No external receipt import appears in this demo. The exact
`draft-noa-scitt-ai-agent-receipt-01` mapping reached an implementation blocker:
its source signature and canonicalization bases cannot populate native
AELITIUM assurance dimensions without changing their meaning. The evidence and
smallest safe alternative are documented in
[`interop/SCITT_AI_AGENT_RECEIPT_01.md`](interop/SCITT_AI_AGENT_RECEIPT_01.md).

## Interpretation boundary

The demo establishes internal consistency of the frozen recorded evidence and
the reported selected hash relationships. It does not establish provider
execution, response causation, trusted historical time, semantic truth,
complete capture, historical occurrence, model drift, authorization, or legal
compliance.
